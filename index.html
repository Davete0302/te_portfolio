04 / CASE STUDY

Sirius POS

A BIR-approved, offline-first point-of-sale system for retail and restaurant operations, built for Android and Windows.

CROSS-PLATFORM POINT OF SALE

Reliable checkout, even when the network isn't.

As Software Engineer II and primary developer, I built core POS workflows, local-first transaction processing, reporting, deployment configuration, and integrations with companion ordering, calculation, and reporting applications.

Internal product · Not publicly released
Role
Software Engineer II · Primary Developer
Platforms
Android · Windows
Technology
Flutter · Dart · Provider · SQLite · SQLCipher
Integrations
REST APIs · Firebase · Pusher/WebSockets · TCP

Core POS & offline-first architecture

  • Built cart, checkout, payments, discounts, taxes, service charges, refunds, voids, and suspended transactions.
  • Persisted transactions locally before upload, with background synchronization, retries, and failed-attempt tracking.
  • Implemented standalone and API-connected modes using shared local storage and transaction-processing logic.
  • Added master-data synchronization for products, pricing, customers, promotions, payment methods, users, and configuration.

Reporting & regulatory workflows

  • Developed sales, product, category, hourly sales, cashier, payment, discount, refund, void, and accountability reports.
  • Implemented X, Y, and Z readings, including sales calculations, reading records, report generation, and end-of-day processing.
  • Worked on BIR-related reporting, e-journals, audit activity, and mandated transaction reporting.

Cross-application integrations

  • Built manual and background order imports for kiosk and e-commerce orders, including modifiers, add-ons, and special requests.
  • Implemented TCP communication with a separate discount-calculation application.
  • Developed Firebase synchronization with a separate reporting application, including offline scenarios.
  • Integrated REST APIs, Pusher/WebSockets, queueing services, and payment gateway verification and status handling.

Configuration & maintenance

  • Developed permissions, product and pricing configuration, promotions, payment methods, branch and terminal settings, and fine-dine layouts.
  • Built initialization and configuration workflows for standalone and API-connected deployments.
  • Modified selected existing printing functionality; the original printing subsystem was implemented by another developer.

Architecture highlights: locally persisted transactions decouple checkout from network availability; shared local data and processing support multiple deployment modes; end-of-day workflows coordinate totals, readings, reports, and maintenance.
